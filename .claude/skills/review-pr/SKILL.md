# このプロジェクトのレビュー

変更の差分を読み、下のチェックリストに沿って確認する。結果は日本語で、PR の説明に貼れる形にまとめる。

## 手順

1. 差分を取る。引数が PR 番号なら `gh pr diff <番号>`、なければ `git diff main...HEAD`。変更ファイルの一覧も見る。
2. `npm run verify` を実行し、結果を記録する（落ちていたらそれが最優先の指摘）。
3. 変更したファイルの種類に応じて、下の該当する観点だけを確認する。該当しない観点は「対象外」と書く。
4. 汎用のバグ検出が必要なら `/code-review` も実行し、結果を合わせる。
5. 指摘を重大度で並べる。

## 観点

### 要件とテスト（すべての変更）
- 機能の追加・変更なら、docs/requirements.md に番号つきの要件があるか。新しい番号は続き番号で、既存の番号を使い回していないか。
- 振る舞いを変えたなら、テスト名の先頭に対応する要件番号があるか。`npm run trace` で存在しない番号の参照がないか。
- 画面・データ・API の変更なら、docs/screens.md、docs/data-model.md も同じ変更で更新されているか。
- バグ修正なら、再発を防ぐテストがあるか。

### 認可と個人情報（backend/src）
- 新しい経路は backend/src/routes.ts の ROUTE_KEYS にあるか。講師専用の機能は `/admin/` 配下か。
- 生徒が他の生徒のデータを読み書きできる経路がないか（sub を呼び出し元から取っているか。リクエストの値を信用していないか）。
- 本名・メールアドレス・電話番号を保存・ログ出力していないか。エラー応答に内部の情報（テーブル名、スタック）を出していないか。
- 正解や解説を、解答前の応答に含めていないか。

### インフラ（infra）
- データを持つリソース（DynamoDB、Cognito）に削除保護（Retain）があるか。置き換えが起きる変更（名前やキーの変更）がないか。
- IAM の権限が広がっていないか。ワイルドカード（`*`）を新たに許可していないか。
- 公開範囲が広がっていないか（S3 の公開、CORS の許可元）。
- AWS のアカウント固定（infra/config.ts の accountId、check-account）を迂回していないか。

### 問題生成とAI利用（backend/src/lib/generation、claude.ts、pricing.ts）
- プロンプトの変更なら、試し生成の結果（承認率、難易度、解説の形式）が PR に書かれているか。書かれていなければ「要確認」にする。
- 費用の記録（使用量を検証より前に記録）と、予算の90%で止まる仕組みが保たれているか。
- 生成した内容を、検証せずに出題対象にしていないか。
- モデル名や API の設定を、設定画面の値ではなくコードに固定していないか。

### 学習ロジック（shared、backend/src/lib/study）
- 日付の区切り（日本時間の午前3時）を `studyDate` 以外で計算していないか。
- カリキュラムの問題数を変えたら、docs/requirements.md の 2.1 と必要な問題数（3.5）の表も更新されているか。

### 画面（frontend）
- スマホ幅（390px）で崩れていないか。操作できる要素が小さすぎないか（目安 44px 以上）。
- エラー時の表示と、読み込み中の表示があるか。
- ダークモード、動きを減らす設定（prefers-reduced-motion）で破綻しないか。

### リポジトリ全体
- API キー、アクセスキー、パスワード、生徒の個人情報が差分に含まれていないか。
- .github/workflows、.claude/hooks、.claude/settings.json の変更は、止める線を弱めていないか。弱める変更は必ず「重大」にして、理由の説明を求める。
- 依存パッケージの追加は、必要性とライセンスを確認する。

## 出力の形式

```
## レビュー結果
- verify: 成功 / 失敗（内容）
- 対象にした観点: （例）要件とテスト、認可、インフラ

### 重大（マージ前に直す）
- ファイル:行 — 指摘と理由

### 要確認（判断が要る）
- ファイル:行 — 指摘と理由

### 提案（任意）
- ファイル:行 — 指摘

### 問題なし
- 確認して問題なかった点を1〜3行
```

指摘がなければ、各見出しを「なし」とする。推測で指摘せず、根拠のあるファイルと行を示す。
