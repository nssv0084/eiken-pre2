# 英検準2級 学習アプリ 要件定義書

- 版: 0.1（ドラフト）
- 作成日: 2026-10-17
- 保守担当: 塾の運営者（1名）

## 1. 目的と前提

個人塾の生徒（2〜10名）が自宅で英検準2級の筆記（リーディング）対策を毎日続け、合格に必要な分野を受験までに2〜3周できるようにする。

| 項目 | 内容 |
|---|---|
| 利用者 | 講師（1〜数名）、生徒（2〜10名） |
| 利用場面 | 生徒の自宅学習。スマホが主、PCでも利用可 |
| 学習時間 | 1日20〜30分 |
| 対象範囲 | 筆記の4形式（下記）。リスニング・面接・ライティングは対象外 |
| 将来拡張 | 3級・2級など他の級への展開を想定し、データは級ごとに区別して持つ |

### 対象とする出題形式

| コード | 大問 | 形式 | 本番の問題数 | 問題文の種類 | アプリでの出題単位 |
|---|---|---|---|---|---|
| vocab | 1 | 短文の語句空所補充 | 15問 | 短文、会話文 | 1問ずつ（4択） |
| conversation | 2 | 会話文の空所補充 | 5問 | 会話文 | 1問ずつ（4択） |
| cloze | 3 | 長文の語句空所補充 | 2問 | 物語文、説明文 | 長文1題に空所2つ（各4択） |
| reading | 4 | 長文の内容一致選択 | 7問 | Eメール、説明文 | Eメール1題に設問3問、説明文1題に設問4問（各4択） |

- 本番のリーディングは全29問。ライティング2題と合わせて80分（2024年度の形式改定後。英検協会公式サイトで 2026-10-17 に確認）。
- 大問4の内訳（Eメール3問、説明文4問）は公式ページに明記がないため、公式の過去問で確認して設定値で調整する。

## 2. 学習の仕組み

### 2.1 30日カリキュラム

[CUR-01] 30日で全形式を一通り学ぶ。これを受験までに2〜3周する。

| 期間 | フェーズ | 1日の内容 | 所要時間の目安 |
|---|---|---|---|
| 1〜10日目 | 語彙・会話の基礎 | 語彙15問、会話文5問、復習 | 約20分 |
| 11〜18日目 | 長文の語句空所補充 | 長文空所1題、語彙10問、会話文2問、復習 | 約25分 |
| 19〜26日目 | 長文の内容一致 | 内容一致1題、語彙8問、復習 | 約25分 |
| 27〜29日目 | 総合演習 | 語彙10問、会話文3問、長文空所1題、内容一致1題、復習 | 約30分 |
| [CUR-03] 30日目 | 模試と振り返り | 本番と同じ29問（語彙15、会話文5、長文空所2、内容一致7）を出題し、周回の結果を表示 | 約45分 |

- [CUR-05] 「復習」は、過去に間違えた問題から最大8問を出す（2.4参照）。
- [CUR-02] 内容一致は、Eメールと説明文を日ごとに交互に出す。
- 30日目だけは本番と同じ量のため、時間が長くなる。
- [CUR-04] 1日分は複数の小セット（5〜10問程度）に分け、途中で中断しても続きから再開できる。

### 2.2 進み方（進度ベース）

- [PRG-01] その日の分を終えたら次の日へ進む。休んだ日の分は後ろにずれる。
- [PRG-02] 1日に進めるのは1日分まで。先取りはできない。早く終わった生徒には自由演習を勧める。
- [PRG-03] 講師の画面には、開始日からの経過日数と実際の進度の差（遅れ）を表示する。

### 2.3 周回

- [CYC-01] 30日目を終えたら次の周に進む。周回数の上限は設けない。
- **1周目**: すべて初めて解く問題。
- [CYC-02] **2周目以降**: 各枠に、前の周までに間違えた同じ形式の問題を優先して割り当てる。残りの枠は新しい問題で埋める。新しい問題が足りない場合は、正解してから最も日数が経った問題を再利用する。

### 2.4 毎日の復習（間違えた問題）

簡易的な間隔反復方式とする。

- [REV-01] 間違えた問題は翌日の復習に出し、そこで正解したら3日後にもう一度出す。
- [REV-02] 2回続けて正解したら復習の対象から外す（当初は「翌日、3日後、7日後」としていたが、「2回続けて正解で外す」と組み合わせると7日後の回が来ないため、2026-10-17 に翌日・3日後に統一）。
- [REV-03] 復習で間違えたら、翌日から数え直す。

### 2.5 自由演習

- [PRC-01] 生徒が形式と問題数（5問・10問・20問）を選んで解く。
- [PRC-02] まだ解いていない問題を優先して出す。
- [PRC-03] 結果は学習記録と復習の対象に反映する。カリキュラムの進度は進まない。

### 2.6 講師の課題

- [ASG-01] 講師が形式と問題数、または問題を直接選んで課題を作り、生徒（個別または全員）に期限付きで配る。
- [ASG-02] 生徒のホームでは、今日のカリキュラムより上に課題を表示する。
- [ASG-03] 講師は課題ごとの完了状況と正答率を確認できる。

### 2.7 続けてもらう仕掛け

- [STK-01] **連続学習日数**: その日のカリキュラム分を終えた日、または10問以上解いた日を「学習した日」とし、連続日数を生徒のホームに表示する。
- [STK-02] **日付の区切り**: 日本時間の午前3時で翌日に切り替える（深夜の学習を前日分として数えるため）。
- [STK-03] **未学習アラート**: 講師の画面で、最後の学習から3日以上空いた生徒を目立たせる。日数は設定で変更できる。

### 2.8 受験日

- [EXM-01] 生徒ごとに受験日を登録できる（講師が設定）。
- [EXM-02] 生徒のホームに受験日までの残り日数を表示する。
- [EXM-03] 今のペースのままだと受験日に何周目の何日目まで進めるかを表示する。2周に届かない見込みのときは、講師の画面に警告を出す。

## 3. 問題の作成と品質管理

### 3.1 方針

- [GEN-01] 過去問は英検協会の著作物のため使用しない。問題はすべてオリジナルとする。
- [GEN-02] 問題は Anthropic API（Claude）で生成する（Amazon Bedrock は使わない）。
- [GEN-03] 講師が手入力で問題を追加・編集することもできる。

### 3.2 生成と検証の流れ

```text
講師が生成を指示（形式・数・テーマ）
  → 生成：Claude が準2級レベルの問題・選択肢・正答・日本語の解説を作る
  → 検証：別の呼び出しで、Claude に正答を見せずに解かせる
           ・解いた答えが正答と一致するか
           ・正解が1つに定まるか
           ・語彙や文法が準2級の範囲か
           ・解説が正しいか
  → 合格：自動で出題対象（承認済み）にする。ランダムに約1割を講師の「確認待ち」に入れる
  → 不合格：破棄し、必要数に届くまで作り直す（上限あり）
```

- [GEN-04] 生成時には、同じ形式の既存の問題文を一部渡し、重複を避ける。
- [GEN-05] 生成した問題には、使ったモデル、検証結果、生成日時を記録する。
- [GEN-06] 生成した問題は、形式（選択肢が4つで重複しない、正解の番号が範囲内、空所の数が正しい）を機械的に検査し、通らないものは破棄する。
- [GEN-07] 検証では、正答を見せずに解かせた答えが正答と一致し、正解が1つに定まり、レベルが合っている問題だけを合格にする。

### 3.3 準2級として適切かの担保

AI の自己判断だけに頼らず、次の4つを組み合わせる。

| 仕組み | 内容 | 判定できること |
|---|---|---|
| [LVL-01] 語彙リストによる機械判定 | 『CEFR-J Wordlist Version 1.6』（東京外国語大学投野由紀夫研究室）で判定する。語彙問題の単語の正解は A2〜B1 なら合格、A1（易しすぎる）・B2（難しすぎる）なら AI 検証の前に不合格。誤りの選択肢の多くが A1 なら確認待ち。長文は本文のうち B2・リスト外の語が8%を超えたら不合格、4%を超えたら確認待ち | 語彙の難しさ（客観的な基準） |
| [LVL-02] AI による難しさの採点 | 検証時に1〜5で採点し、3（標準）と4（やや難しめ）だけを合格にする | 語彙以外も含めた難しさ（補助的） |
| [LVL-03] 講師による全問確認と見本 | 形式ごとに、講師の承認が目標数（語彙30、会話文10、長文空所5、内容一致5）に届くまで、AI 検証に合格した問題をすべて確認待ちにする。講師が「準2級らしい」と判断した問題を見本にし、以後の作問で難しさの目安としてAIに渡す | 人の目による基準合わせ |
| [LVL-04] 生徒の正答率による見直し | 運用開始後、問題ごとの正答率が高すぎる（95%以上）・低すぎる（30%未満）問題を講師の確認待ちに回す（ステップ3以降で実装） | 実際の難しさ |

- しきい値は仮の値。講師の確認結果と正答率を見て調整する。
- 熟語・文法の問題は語彙リストでは判定できないため、AI の採点と講師の確認で担保する。
- [LVL-05] アプリ内とリポジトリにCEFR-J Wordlistのクレジットを表記する（利用条件: 適切な引用があれば商用も無償）。

### 3.4 生徒からの報告

- [RPT-01] 生徒は解答後の画面で「問題がおかしい」を報告できる（理由を選択し、任意でコメントを書く）。
- [RPT-02] 報告された問題は、講師が確認するまで新たに出題しない。
- [RPT-03] 講師は報告を見て、修正・無効化・問題なしのいずれかを選ぶ。

### 3.5 必要な問題数（3周分の目安）

| 形式 | 1周あたり | 3周分（弱点の再出題を考慮した新問の合計） |
|---|---|---|
| 語彙 | 約340問 | 約680問 |
| 会話文 | 約80問 | 約160問 |
| 長文の語句空所補充 | 約12題 | 約24題 |
| 長文の内容一致 | 約13題 | 約26題 |

まず1周目の分を作り、生徒の利用状況を見てから2周目以降の分を追加する。

### 3.6 在庫の見通し

講師が「あと何日分の問題があるか」「何をいくつ作ればよいか」を、手計算せずに分かるようにする。

- [STK-04] 講師のダッシュボードに、形式ごとの在庫の見通しを表示する。表示する値は、出題できる問題の数、最も進んでいる生徒を基準にした「あと何日分か」、現在の周の終わりまでに足りない数、作る数の目安。
- [STK-05] 「あと何日分か」は、基準の生徒が毎日1日分ずつ進むと仮定し、カリキュラムの各日の出題数（復習を除く）を順に引いて、在庫が足りなくなる日の手前までの日数とする。現在の周の終わりまで足りるときは「周の終わりまで足りる」と表示する。
- [STK-06] 出題できる問題とは、承認済みの問題だけを指す。確認待ち・報告あり・無効の問題は数えない。
- [STK-07] 2周目以降は、前の周に出した問題の再利用を見込まず、すべて新しい問題で進める場合の数字（上限の見積り）とする。そのことを画面に明記する。
- [STK-08] あと何日分かが警告日数（初期値7日）より少ない形式を警告として目立たせる。警告日数は設定画面で変更できる。
- [STK-09] 作る数の目安は、足りない数に、出題前の無効化や報告で減る分として10%を足して切り上げた数とする。生成の1回あたりの上限（語彙30、会話文15、長文空所5、内容一致5）で割った回数も併記する。
- [STK-10] 長文の内容一致は、Eメールと説明文を合わせた題数で見通す。ジャンル別の内訳は出さない。
- [STK-11] 生徒が1人もいないときは、見通しを出さず「生徒を追加すると表示されます」と表示する。

## 4. API費用の管理

| 項目 | 内容 |
|---|---|
| 初期予算 | 5,000円（約$33）を上限とする |
| 使用モデル | Claude Opus 5.5（生成・検証とも）。設定で変更できる |
| 見積もり | 3周分のストック作成で約2,000〜3,000円 |
| まとめて作る場合 | バッチAPI（料金50%引き、結果は最大24時間以内） |
| 少しだけ追加する場合 | 通常のAPI（即時に生成） |
| [COST-01] アプリ側の管理 | 応答に含まれるトークン使用量から費用を計算して累計を記録する。講師画面に「使用額／予算」を表示し、予算の90%に達したら生成を止める |
| 外側の安全策 | Claude Console で月の利用上限を $30 に設定する |

## 5. 利用者とアカウント

| 項目 | 内容 |
|---|---|
| [ACC-01] 講師アカウント | 初回のみコマンドで作成。以降は管理画面から追加できる |
| [ACC-02] 生徒アカウント | 講師が管理画面で作成。ログインIDは英数字（例: taro01）、表示名はニックネーム |
| [ACC-03] 個人情報 | 本名・メールアドレス・電話番号は保持しない |
| [ACC-04] 初回ログイン | 講師が発行した仮パスワードでログインし、自分のパスワードに変更する |
| [ACC-05] パスワード忘れ | 講師が管理画面から仮パスワードを再発行する（生徒が自分で再設定する機能はない） |
| [ACC-06] パスワード規則 | 8文字以上、数字を含む |
| [ACC-07] 生徒の削除 | アカウントと学習記録をまとめて削除する |

## 6. 講師が見る情報

- [DSH-01] 生徒一覧: ニックネーム、今何周目の何日目か、遅れの日数、最後に学習した日、連続学習日数、全体の正答率、受験日までの残り日数、アラート
- [DSH-02] 生徒ごとの詳細: 形式別の正答率、日別の学習量と正答率、周回ごとの成績、苦手な問題
- [DSH-03] 問題: 形式別の在庫数、確認待ちの件数、報告された件数
- [DSH-04] API費用: 使用額と予算

## 7. 非機能要件

| 項目 | 内容 |
|---|---|
| [NFR-01] 対応端末 | スマホ（iOS Safari、Android Chrome）が主。PCのブラウザでも使える |
| [NFR-02] ホーム画面への追加 | PWAとしてホーム画面に追加し、アプリのように起動できる |
| [NFR-03] 応答時間 | 問題の表示と採点は1秒以内を目標とする |
| 可用性 | 個人塾の規模のため、特別な冗長化は行わない（AWS マネージドサービスの標準水準） |
| [NFR-04] セキュリティ | HTTPS 通信。Cognito による認証。講師機能は講師グループのみ。APIキーは Secrets Manager に保管 |
| [NFR-05] バックアップ | DynamoDB のポイントインタイムリカバリを有効にする |
| [NFR-06] 監視 | AWS 予算アラート（月額が一定額を超えたらメール）。Lambda のエラー通知 |
| 保守 | サーバーの管理が要らない構成にする。デプロイは `npm run deploy` の1コマンド |
| AWS 月額の目安 | 1〜2ドル程度（Secrets Manager 約$0.4、そのほかは無料枠でほぼ収まる見込み） |

## 8. システム構成

| 要素 | 採用するもの |
|---|---|
| 画面 | React（Vite）+ TypeScript。S3 に配置し CloudFront で配信 |
| ドメイン | `eiken.ikehiroki.com`（Route 53。証明書は ACM） |
| 認証 | Amazon Cognito（講師グループ・生徒グループ） |
| API | API Gateway（HTTP API）+ Lambda（Node.js、TypeScript） |
| 問題生成 | 生成用の Lambda を非同期で起動し、Anthropic API を呼ぶ |

| 秘密情報 | Secrets Manager（Anthropic APIキー） |
| インフラ管理 | AWS CDK（TypeScript）。npm workspaces のモノレポ |
